WORD HEADING 2: 5.2 Qualitative Inspection of the 3-Class Mapping

We applied the threshold mapping (described in Section 4.4) to the catalogue's 346 reviews and looked at the per-film distributions shown in the application's hype dashboard. Aggregated across the whole catalogue, the distribution is approximately:

- 70 percent positive
- 17 percent neutral
- 13 percent negative

The neutral bucket is dominated by short reviews of the form "It was okay", "Worth a watch but not memorable", and "Mixed feelings about this one". For all of these, the model returns probabilities in the 0.35 to 0.65 band, which matches the linguistic intuition behind the mapping: reviews that read as ambivalent end up in the neutral class because the model itself is least confident about them.

WORD HEADING 2: 5.3 Latency

On Apple Silicon (M-series GPU using the MPS backend), the median single-text inference latency is around 50 milliseconds. Batch inference at the maximum batch size of 64 reviews completes in around 380 milliseconds, which is roughly 6 milliseconds per review once the model is warm.

These numbers are well within the limits of an interactive web request, and they confirm the practical reason for choosing a distilled model over the full BERT-base: the latency budget is small enough that a user does not notice the inference happening in the background.

WORD HEADING 2: 5.4 Discussion

The threshold mapping is the weakest part of the system. The binary classifier reaches 91.5 percent accuracy on a labelled held-out test set, but the 3-class output that the user actually sees is generated by a heuristic threshold. The threshold values (0.65 and 0.35) were not learned from data, and we do not have a labelled neutral set on which to evaluate them. A more principled approach would either (a) collect a small labelled neutral set and tune the thresholds on it, or (b) replace the binary base model and fine-tune on a 3-class corpus such as SST-5. We document this limitation clearly in the in-app model card so that users are not misled about how the neutral class is produced.

Strict mode pays off in practice. Switching from a permissive fallback to a strict-error model surfaced exactly one outage during development: a stale uvicorn process held port 8001 long enough that a fresh pnpm dev invocation could not bind. Without strict mode, this would have silently produced lexicon-based labels for several hours of catalogue browsing without anyone noticing. The general lesson is that in any pipeline that depends on a network service, "unreachable" must be distinguished from "returned a normal response" if the consumer cannot tolerate degraded input.
